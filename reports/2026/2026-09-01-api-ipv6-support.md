# api.openai.com への接続で IPv6 が利用可能に

## 概要

2026 年 9 月 1 日付の OpenAI API Changelog にて、`api.openai.com` への接続で IPv6 が利用可能になったことが発表された。これまで IPv4 経由での接続が前提だった OpenAI API エンドポイントに対し、IPv6 プロトコルによる接続が可能になる。

Changelog のエントリは "Connections to `api.openai.com` can now use IPv6." という簡潔な記載のみで、IPv6 アドレス範囲、DNS レコードの詳細、移行手順などの追加情報は現時点で Changelog には含まれていない。

## 主な内容

### 変更内容

- **対象エンドポイント**: `api.openai.com`
- **変更点**: IPv6 プロトコルでの接続に対応

IPv4 での接続は引き続き利用できるため、既存のクライアントに変更は不要である。デュアルスタック環境のクライアントは、OS や HTTP ライブラリの名前解決の挙動 (Happy Eyeballs など) に応じて、IPv6 経由で接続する可能性がある。

### 背景: IPv6 対応の一般的な意義

IPv6 対応は、以下のような環境で API を利用する開発者にとって意味を持つ。

- **IPv6 オンリーのネットワーク**: NAT64/DNS64 などの変換機構を経由せずに直接接続できる可能性がある
- **モバイルネットワーク**: 多くの通信事業者が IPv6 を優先するネットワークを運用している
- **クラウド環境**: IPv6 オンリーのサブネットや、IPv4 アドレスコストの削減を目的とした構成での利用

なお、これらは IPv6 対応一般に関する説明であり、OpenAI が公式に言及した内容ではない点に注意。

## 開発者への影響

- **既存アプリケーション**: 変更は不要。IPv4 での接続は引き続き動作する
- **デュアルスタック環境**: クライアントの名前解決の挙動によっては、今後 IPv6 経由で `api.openai.com` に接続される可能性がある
- **ファイアウォール / egress 制御**: IPv4 アドレスベースで OpenAI API への通信を許可している環境では、IPv6 経由の接続がブロックされる、あるいは意図せず許可される可能性がある。egress ルールを IP アドレスで管理している場合は、IPv6 の扱いを確認することを推奨する。公式の IPv6 アドレス範囲は Changelog には記載されていないため、必要に応じて公式ドキュメントやサポートで最新情報を確認すること
- **プロキシ / 監視**: 接続ログや監視ツールで送信元・宛先アドレスを扱っている場合、IPv6 アドレス形式のログが出力される可能性を考慮する

`api.openai.com` が IPv6 接続に対応した。既存の IPv4 クライアントへの影響はないが、デュアルスタック環境やファイアウォールで egress 制御を行っている環境では、IPv6 経由の接続が発生し得る点を確認しておくとよい。Changelog の記載は一文のみであり、IPv6 アドレス範囲などの詳細は公式ドキュメントの更新を待つ必要がある。
