## 概要

OpenAI は、金融機関向け AI スタートアップ Terminal X の GPT-6.1 Sol 活用事例を公開した。Terminal X は、シニア投資家の退職とともに投資判断の「推論」が失われる問題を「メモリー負債 (memory debt)」と呼び、これを解消するための「Capital Memory」OS を提供している。同社の Eval Agent は 54 項目のルーブリックで全出力を採点しており、500 件の採点判断において GPT-6.1 Sol はシニアの人間レビュアーと 88.6% 一致した。これは次点モデルの 86.4% を 220 ベーシスポイント上回る結果である。

さらに、ファンドのマンデート (運用方針) からの逸脱である「スタイルドリフト」の検出件数は次点モデルより約 25% 多く、クエリあたりのコストは約 30% 低い (速度は同等)。CEO の Hyun Hong 氏は、GPT-6.1 Sol の長文コンテキスト推論とトークン効率が、より深い評価パイプラインの構築を可能にしたと述べている。

## 主な内容

### 「メモリー負債」と Capital Memory OS

投資判断の根拠はシニア投資家の頭の中にあり、退職時に文書は残っても推論そのものは失われる。Terminal X はこの問題を「memory debt」と名付け、Capital Memory OS によって解消を図る。

導入にあたっては、JPMorgan や Blackstone 出身の金融専門家であるフォワードデプロイドエンジニアが顧客先に数週間常駐する。信頼されてきた投資メモをリバースエンジニアリングし、与信審査の手順や共同投資チームの情報源といった文書化されていないプロセスを抽出したうえで、資産クラス・戦略別にカスタマイズした数百のエージェントに投資手法をエンコードする。エージェントはオンプレミスまたは顧客自身のクラウドに展開され、顧客が所有する。

### モデルの役割分担とファームメモリー

Terminal X はタスクの性質に応じてモデルを使い分けている。

- **GPT-6.1 Sol**: 判断力と巨大なコンテキストウィンドウが必要な段階 (投資テーゼの統合、重要論点の特定、マンデート適合性の評価)
- **GPT-6 Luna**: トークン効率が重視される大量処理ステップ

エージェントは各社のプライベートデータルーム内で稼働し、英語・韓国語・日本語・中国語の文書を処理する。学習内容は「firm Memory」(過去の分析、委員会決定、ワークフロー指示、ハウスビューを含むバージョン管理された記録) として保存される。全クエリは監査可能であり、実行ステップ、取得ソース、使用モデル、推論の全履歴が残る。

### Eval Agent による品質評価

Eval Agent は全出力を 54 項目のルーブリックで評価する。評価項目には、数値・コンプス (比較対象企業データ)・引用の出典確認、ナラティブの整合性、ハウスビューとの一致が含まれる。不合格の場合は理由と修正案を付与し、その内容は新たなワークフロー指示やテストケースとして Memory に蓄積される。

GPT-6.1 Sol の成果は以下の通り。

- **88.6%**: 500 件の採点判断でシニアの人間レビュアーと一致した割合 (次点モデルは 86.4%、220 ベーシスポイントの改善)
- **約 25%**: 「スタイルドリフト」の検出が次点モデルより多かった割合。例として、NAV ディスカウントの非公開化案件を探すバイアウトファンドが、市況転換時にディストレスト債権やレスキューファイナンスを推奨してしまう逸脱が挙げられている
- **約 30%**: クエリあたりのコストが次点モデルより低い割合 (速度は同等)

このトークン効率により、同じ予算内でより深いレビュー (マンデート照合 → 直近案件照合 → 不確実な判定の再実行と照合) を構築できるようになった。

### 導入効果と利用実績

- あるプライベートエクイティファームは、デューデリジェンスと投資メモの自動化で年換算 240 万ドルの削減を報告
- firm Memory は 1,700 件、カスタムワークフロー実行は 100 万件超
- 週間アクティブユーザーは月間アクティブユーザーの 81%

CEO の Hyun Hong 氏は「This helps our Eval Agents make investment judgment measurable and auditable. (これにより、Eval Agent は投資判断を測定可能かつ監査可能なものにできる)」と述べている。CTO の Ken Lee 氏は、全回答が評価され、アナリストの修正がシステムの学習につながるため、使うほど自社チームのように思考するようになると説明している。

## 開発者・企業への影響

- **LLM-as-a-Judge の実務水準の実証**: 54 項目のルーブリックに基づく Eval Agent がシニア投資家の判断と 88.6% 一致した事例は、評価エージェントを本番の品質管理に組み込む設計の参考になる
- **判断系と大量処理系のモデル使い分け**: 判断力が必要な段階に GPT-6.1 Sol、トークン効率が重要な大量処理に GPT-6 Luna という役割分担は、コストと品質を両立するマルチモデル構成の実例である
- **コスト効率が評価の深さに転化**: クエリあたり約 30% のコスト低減を、同一予算内での多段レビュー (マンデート照合、直近案件照合、不確実な判定の再実行) に充てる設計は、モデル効率の活かし方として示唆に富む
- **監査可能性とデータ主権**: 実行ステップ・取得ソース・使用モデル・推論履歴をすべて記録し、エージェントを顧客のオンプレミスまたはクラウドに展開して顧客が所有する構成は、規制産業での AI 導入の要件を満たすパターンである
- **フィードバックの資産化**: 不合格理由や修正案、アナリストの修正をワークフロー指示やテストケースとして firm Memory に蓄積する仕組みは、利用するほど組織固有の判断基準を学習するシステム設計の好例である
