API 更新

🎙️ GPT-Live-1.1 リリースと WebRTC スタンバイ設定の導入

📅 2026-11-19

ソース: OpenAI API Changelog / カテゴリ: 新機能・API 更新

概要

🗣️

新モデル gpt-live-1.1 を Live API 向けにリリース

Live API (v1/live/sessions) 向けの全二重 (full-duplex) 音声モデル。話しながら聞くことができ、多言語音声会話での発音・アクセントの一貫性・文字起こし精度が向上した。

✍️

委譲指示を平易な自然言語で記述可能に

バックエンドへのタスク委譲を特殊トークンではなく、"Delegate to the backend" のような平易な自然言語で記述できるようになった。

⏸️

WebRTC スタンバイ設定を追加

GPT-Live-1 / GPT-Live-1.1 の WebRTC セッションで、非アクティブ時に推論を一時停止し、誰かが話すと自動的に再開する仕組みが利用可能になった。

💰

スタンバイ中は低レート課金でコスト削減

スタンバイ中はアクティブ時より低いレートで課金されるため、長時間接続を維持するボイスアプリケーションのコスト削減につながる。

🔁

移行はモデル名の変更だけ

既存の Live セッション設定でモデル名を gpt-live-1.1 に変更するだけで利用できる。

Before / After: 委譲指示の書き方

委譲指示の書き方は旧モデルから大きく簡素化された。プロンプト構成ガイドでは、Backchannel policy、Interruption policy、Delegation policy の 3 つの見出しを保持したテンプレートから始めることが推奨されている。

多言語音声会話での発音と文字起こし精度が GPT-Live-1 から向上した。

🎵 アクセントの一貫性

言語をまたいでもアクセントと声の一貫性を維持する。

GPT-Live-1.1 は GPT-Live-1 とは別枠の同時セッション制限を持ち、段階的な移行や並行運用がしやすい。

API 変更点

🆕 新モデル: gpt-live-1.1

既存の Live セッション設定でモデル名を gpt-live-1.1 に変更するだけで、多言語音声品質の改善と平易な自然言語での委譲指示を利用できる。対応エンドポイントは Live (v1/live/sessions) のみ。

⚙️ WebRTC スタンバイ設定パラメータ

パラメータ内容
session.wake_policy.typespeech に設定すると、発話があるまで推論を開始せず待機
session.wake_policy.vad_threshold0〜1 (デフォルト 0.5)。高いほど推論開始に強い発話の証拠が必要
session.idle_timeout_s5〜60 の整数。入出力トランスクリプトがこの秒数ない場合にスタンバイへ移行

🔄 動作の仕組み

  • 一時停止: アイドルタイムアウトに達すると推論が停止しスタンバイに入る。接続とセッション ID は維持される
  • 再開: ユーザーが話すとセッションが再開し、会話履歴が復元される。VAD しきい値は初回ウェイク時と各ポーズ後に適用される
  • イベント通知: session.paused (スタンバイ移行) と session.resumed (推論準備完了) をサイドバンドまたは WebRTC データチャネルで監視できる
  • idle_timeout_s を省略した場合、初回ウェイク後はセッション終了まで推論がアクティブのまま維持される

⚠️ 注意点

  • スタンバイ中もマイクのトラックはアクティブに保つ必要がある
  • マイクのミュートはセッションをアクティブなままにする (スタンバイとは別の動作)
  • スタンバイ後、短い発話への最初の応答は通常より時間がかかる場合がある
  • 長い空白期間が想定される場合は、スタンバイではなくセッションを閉じて後で新規作成する選択肢も推奨されている

コードサンプル

既存の Live セッション設定でモデル名を gpt-live-1.1 に変更し、スタンバイ関連のパラメータを追加する例 (ドキュメント記載のパラメータに基づく構成例)。

Bash Live セッション作成 (スタンバイ設定付き) 
curl -X POST https://api.openai.com/v1/live/sessions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-live-1.1",
    "instructions": "You are Aki, a calm, friendly voice assistant for a booking service.\n\n## Backchannel policy\nUse brief acknowledgements while listening.\n\n## Interruption policy\nStop speaking immediately when the user starts talking.\n\n## Delegation policy\nDelegate to the backend when the user asks to check availability or create, change, or cancel bookings. Do not delegate for greetings or repeated results. Do not guess the result while waiting.",
    "wake_policy": {
      "type": "speech",
      "vad_threshold": 0.5
    },
    "idle_timeout_s": 30
  }'

クライアント側では、スタンバイへの移行と再開をイベントで監視する。

JavaScript WebRTC データチャネル経由でセッションイベントを監視する例 
// WebRTC データチャネル経由でセッションイベントを監視する例
dataChannel.addEventListener("message", (event) => {
  const msg = JSON.parse(event.data);

  switch (msg.type) {
    case "session.paused":
      // スタンバイに移行 (接続とサイドバンドは開いたまま)
      // マイクのトラックはアクティブに保つ
      showStatus("Standby");
      break;
    case "session.resumed":
      // 推論の準備完了 (初回ウェイクを含む)
      showStatus("Active");
      break;
  }
});

ユースケース / 開発者への影響

🏢 長時間稼働するボイスアプリのコスト最適化

受付、カスタマーサポート、会議アシスタントなど、長時間接続を維持するボイスアプリでは、WebRTC スタンバイによりアイドル時間のコストをアクティブ時の 40% ($0.02 / 分) に抑えられる。

🌐 多言語対応の音声アシスタント

既存の Live セッション設定でモデル名を gpt-live-1.1 に指定するだけで、多言語音声会話での発音・アクセントの一貫性・文字起こし精度の改善を利用でき、移行が容易。GPT-Live-1 とは別枠の同時セッション制限を持つため、段階的な移行や並行運用がしやすい。

🛠️ 保守しやすい委譲プロンプトの設計

特殊トークン (<|SpawnThinking|>) が不要になり、予約の確認・作成などバックエンドへの委譲タイミングを平易な自然言語で記述できるため、プロンプトの可読性と保守性が向上する。

設計上の考慮点: スタンバイ後の最初の応答は遅延する可能性があるため、idle_timeout_s の値はユーザー体験とコスト削減のバランスを見て調整する必要がある。

まとめ

GPT-Live-1.1 は、多言語音声会話での発音・アクセントの一貫性・文字起こしを改善し、バックエンドへの委譲を平易な自然言語で記述できるようにした Live API 専用モデルである。同時に導入された WebRTC スタンバイ設定は、wake_policy と idle_timeout_s の 2 つの設定で非アクティブ時の推論を一時停止し、スタンバイ中はアクティブ時の 40% の料金で接続を維持できる。音声アシスタントを長時間稼働させる開発者にとって、品質とコストの両面で実用的なアップデートとなっている。
