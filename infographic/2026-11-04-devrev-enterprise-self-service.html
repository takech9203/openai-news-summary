💡 概要

🖥️

「Computer」と「Operator」を構築

サービスチームやオペレーションチームが、顧客・従業員からの難易度の高いリクエストを完了まで遂行できるよう支援するプロダクト。ライブデータを横断して推論するよう設計され、アクションは取り消し可能、回答は情報ソースへ遡れる (CTO の Ahmed Bashir 氏)。

🧠

OpenAI モデル + 自社ハーネス

GPT-6 Astra や GPT-6.1 Sol を含む OpenAI モデルを、企業ナレッジへの接続とエージェントが実行できるアクションの制御を担う自社ハーネスと組み合わせて活用。

⚡

速度とコストを維持した推論能力

OpenAI モデルは、顧客・従業員へのサービス提供に求められる速度とコストを維持しつつ、推論能力と信頼性を提供するものと位置づけられている。

📊

独自ベンチマーク Enterprise-Bench で評価

実企業環境を想定した独自ベンチマークで性能を評価。GPT-6.1 Sol は良好な結果を示している。

👨‍💻

社内開発は Codex に全面移行

エンジニアリングチーム全員が Codex を使用。複数のコーディングツールを検討した結果、Cursor のライセンスを解約し完全移行した。

「適切な推論能力を持ち、信頼でき、高度にアラインされていること。そして最も重要なのは、レイテンシの観点で機能しなければならないことです」

— Ahmed Bashir 氏 (DevRev CTO)

📌 主な内容

🔗 企業コンテキストと連携する AI

OpenAI モデルは、Computer と Operator の両方で推論・プランニング・ツール選択を担当。Agent Studio では、ユーザーが AI との対話を通じてツールの振る舞いを記述し、一部の挙動を固定ルールで定義できる。

DevRev は、企業コンテキストの供給・権限の強制・アクションの制御を行うソフトウェアとモデルを組み合わせてテスト。Enterprise-Bench では、データに複数のバージョンが存在する、情報が異なるシステムに分散している、アクセス権がロールに依存するといった状況での性能を評価している。

Bashir 氏によれば GPT-6.1 Sol はこれらの評価で良好な結果を示し、ニュアンス理解・応答速度・持続可能なコストについて「完璧にバランスが取れていると思います」と述べている。

💻 Codex による開発とセールスデモ構築

DevRev 社内では、エンジニアリングチーム全員が Codex を使用。複数のコーディングツールを検討した結果、採用は自然発生的に広がり、インタビュー時点で完全に Codex へ移行し、Cursor のライセンスを解約していた。

「開発者は本当に最高のツールだけを求めており、彼らを欺くことはできません」と Bashir 氏。エンジニアたちは Codex の継続利用を明確に望んだという。

また、セールスエンジニアは国際カンファレンスのブース向けデモの作成に GPT-6 Astra を活用している。

🚀 顧客・従業員への迅速な対応

支援リクエストに応じて、Operator が問題を理解し承認済みのアクションを実行するか、適切な担当者が対応できるよう Computer にルーティング。Decisions API や Ultrafast が、各ステップで深い推論を必要とせずワークフローを迅速に完了させる助けになると Bashir 氏は見ている。

依存する情報が変化し続けるため、固定ルールでの定義が困難かつ高コストな判断もある。ビルダーがロジックの多くを対話的に記述し、タスクごとに適切な種類のインテリジェンスを選択できるようにしたいという。「これらは数分ではなく数秒で実行・完了できなければなりません」

🎯 セルフサービスの約束を実現する

次の目標は、アクションの追跡可能性・権限管理・取り消し可能性を維持したまま、Operator がより長く要求の厳しいリクエストを担えるようにすること。

ナレッジベースの回答検索、プランのアップグレード、返金対応といった定番のサポートタスクは始まりに過ぎず、「セルフサービスの約束を本当に実現したい」と Bashir 氏。OpenAI のフロンティアインテリジェンスを活用し、Computer と Operator が企業ナレッジと制御機構を備えて本人に代わって行動し、より複雑なリクエストを解決まで遂行できる姿を目指す。

「Codex は圧倒的に最高の体験だと考えています」

— Ahmed Bashir 氏 (DevRev CTO)

👩‍💻 開発者への影響

🧪 ハーネスと組み合わせた実環境評価

エンタープライズ向け AI エージェントでは、モデル単体の性能だけでなく、企業コンテキストの供給・権限の強制・アクション制御を行うハーネスとの組み合わせでの評価 (DevRev の Enterprise-Bench のような実環境ベンチマーク) が重要になる。

⚖️ GPT-6.1 Sol というバランス型の選択肢

GPT-6.1 Sol は、推論能力・レイテンシ・コストのバランスが求められる顧客・従業員対応ユースケースでの選択肢となる。

🛡️ エージェント導入の設計原則

アクションの取り消し可能性、ソースへの遡及性、ロールベースの権限管理は、本人に代わって行動するエージェントを企業に導入する際の設計原則として参考になる。

⚡ タスクに応じたインテリジェンスの使い分け

すべてのステップで深い推論を使うのではなく、タスクごとに適切な種類のインテリジェンス (Decisions API、Ultrafast など) を使い分ける設計が、秒単位でのワークフロー完了につながる。

📝 まとめ

DevRev は、GPT-6 Astra と GPT-6.1 Sol を自社ハーネスと組み合わせ、ライブデータを横断して推論し、取り消し可能かつソースに遡れるアクションを実行する「Computer」と「Operator」を構築した。GPT-6.1 Sol は、独自ベンチマーク Enterprise-Bench の評価で、リクエストのニュアンス理解・応答速度・持続可能なコストのバランスに優れると評価されている。社内開発では Codex を全面採用し、今後は Decisions API や Ultrafast を活用して、より長く複雑な顧客・従業員リクエストを数秒で完了するセルフサービスの実現を目指している。
