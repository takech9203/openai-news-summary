📅 2026-10-20 | OpenAI News

概要

🧠

「メモリー負債」の解消を目指す Capital Memory OS

シニア投資家の退職とともに投資判断の「推論」が失われる問題を「memory debt」と呼び、金融機関向け AI スタートアップ Terminal X が Capital Memory OS でこれを解消する。

📋

54 項目ルーブリックの Eval Agent が全出力を採点

数値・コンプス・引用の出典確認、ナラティブの整合性、ハウスビューとの一致を評価。500 件の採点判断で GPT-6.1 Sol はシニアの人間レビュアーと 88.6% 一致した。

⚖️

判断系と大量処理系でモデルを使い分け

判断力と巨大なコンテキストウィンドウが必要な段階に GPT-6.1 Sol、トークン効率が重視される大量処理に GPT-6 Luna を割り当てるマルチモデル構成。

🔍

スタイルドリフト検出 約 25% 増、コスト 約 30% 低減

ファンドのマンデート (運用方針) からの逸脱の検出件数は次点モデルより約 25% 多く、クエリあたりのコストは約 30% 低い (速度は同等)。

🔐

監査可能性とデータ主権

エージェントはオンプレミスまたは顧客自身のクラウドに展開され、顧客が所有する。全クエリで実行ステップ、取得ソース、使用モデル、推論の全履歴が残る。

モデルの役割分担

GPT-6.1 Sol

🎯 判断力が必要な段階

判断力と巨大なコンテキストウィンドウが必要な段階を担当。投資テーゼの統合、重要論点の特定、マンデート適合性の評価に使用。長文コンテキスト推論とトークン効率が、より深い評価パイプラインの構築を可能にした。

GPT-6 Luna

⚡ 大量処理ステップ

トークン効率が重視される大量処理ステップを担当。コストと品質を両立するマルチモデル構成を実現している。

Eval Agent と firm Memory の仕組み

  • Eval Agent は全出力を 54 項目のルーブリックで評価 (数値・コンプス・引用の出典確認、ナラティブの整合性、ハウスビューとの一致)
  • 不合格の場合は理由と修正案を付与し、新たなワークフロー指示やテストケースとして Memory に蓄積
  • 学習内容は「firm Memory」(過去の分析、委員会決定、ワークフロー指示、ハウスビューを含むバージョン管理された記録) として保存
  • エージェントは各社のプライベートデータルーム内で稼働し、英語・韓国語・日本語・中国語の文書を処理
  • トークン効率により、同じ予算内でより深いレビュー (マンデート照合 → 直近案件照合 → 不確実な判定の再実行と照合) を構築
  • 導入時は JPMorgan や Blackstone 出身のフォワードデプロイドエンジニアが顧客先に数週間常駐し、投資メモをリバースエンジニアリングして数百のエージェントに投資手法をエンコード

ユースケース

💼 デューデリジェンスと投資メモの自動化

あるプライベートエクイティファームは、デューデリジェンスと投資メモの自動化により年換算 240 万ドルのコスト削減を報告した。

🚨 スタイルドリフト (マンデート逸脱) の検出

ファンドの運用方針からの逸脱を検出する。例として、NAV ディスカウントの非公開化案件を探すバイアウトファンドが、市況転換時にディストレスト債権やレスキューファイナンスを推奨してしまう逸脱が挙げられている。GPT-6.1 Sol は次点モデルより約 25% 多く検出した。

📚 投資判断ナレッジの継承と学習

全回答が評価され、アナリストの修正がシステムの学習につながるため、使うほど自社チームのように思考するようになる (CTO の Ken Lee 氏)。不合格理由や修正案は firm Memory に蓄積され、組織固有の判断基準を学習する。

開発者・企業への影響

  • LLM-as-a-Judge の実務水準の実証: 評価エージェントを本番の品質管理に組み込む設計の参考になる
  • 判断系と大量処理系のモデル使い分け: コストと品質を両立するマルチモデル構成の実例
  • コスト効率が評価の深さに転化: 約 30% のコスト低減を同一予算内での多段レビューに充てる設計
  • 監査可能性とデータ主権: 全履歴の記録と顧客所有の展開は、規制産業での AI 導入要件を満たすパターン
  • フィードバックの資産化: 修正をワークフロー指示やテストケースとして蓄積し、組織固有の判断基準を学習
