Product / API (新機能 GA)

Decisions API が一般提供開始: 高速・低コストな意思決定をアプリケーションに

GPT-6 Luna 上に構築され、答えが限定された質問 (bounded answers) に知能を集中。テキスト・画像・構造化入力からほぼリアルタイムの意思決定を実現し、Responses API 経由の GPT-6 Luna より最大 10 倍高速に動作

📅 2026-10-22 | ソース: OpenAI News / OpenAI API Changelog

概要

🚀

Decisions API が一般提供 (GA) に

アプリケーションやエージェントが行う入力の分類、リクエストのルーティング、次のアクションの選択といった小さな意思決定を、GPT-6 Luna の知能でほぼリアルタイムに処理。個々は単純でも大規模化するとレイテンシとコストが積み上がる課題を解決する。

⚡

Responses API 経由の GPT-6 Luna より最大 10 倍高速

答えが限定された質問 (bounded answers) に Luna の知能を集中させることで、テキスト、画像、構造化入力からの意思決定を高速化。アジアの複数リージョンで容量を追加し、レイテンシを継続的に改善している。

💰

入力 $0.10 / 100 万トークン、出力トークンは課金なし

キャッシュ済み入力は $0.01 / 100 万トークン。課金は入力トークンのみで出力トークンへの課金はないため、コスト見積もりが入力トークンのみで完結する。

🧩

predicate / choice / score の 3 つの型付き回答

開発者は質問と許容される回答を定義し、テキスト、画像、ネイティブ JSON としてコンテキストを渡す。API は 3 種類のいずれかの回答タイプを返し、アプリケーションは次の動作を決定できる。

🎙️

GPT-Live とのネイティブ統合でリアルタイム音声体験に対応

ライブ会話中の高速で焦点を絞った意思決定を支援。エスカレーション判断やアバターの表情制御など、リアルタイム性が求められるユースケースに組み込める。

Before / After: ベータから GA へ

2026 年 10 月 6 日のパブリックベータ公開 (gpt-6-luna、テキストと画像を Responses API の 10 倍速で型付き回答に変換) 以降、GA までに多くの機能が追加された。

Before (パブリックベータ: 2026-10-06)

  • テキストと画像の入力に対応
  • Responses API の 10 倍速で型付き回答に変換
  • 質問数上限は 1 リクエストあたり 200 問
  • GPT-Live 統合なし
  • プロンプトキャッシュなし
  • 地域内処理 (inference residency) なし

After (GA: 2026-10-22)

  • GPT-Live とのネイティブ統合でライブ会話中の意思決定に対応
  • プロンプトキャッシュ (API Changelog ではプロンプトキャッシュ共有と記載) に対応
  • 米国と EU での推論の地域内処理が利用可能
  • ネイティブ JSON 入力 (input_json) で構造化データをそのまま渡せる
  • 質問インストラクション内に画像を含められる
  • 質問数上限が 200 問から 400 問へ倍増
  • アジアの複数リージョンで容量を追加しレイテンシを継続改善

API 変更点 (ベータ → GA)

✅ 一般提供 (GA) 開始

2026 年 10 月 22 日に GA を発表。GPT-6 Luna を専用 Decisions エンドポイント経由で利用し、本番ワークロードに組み込める。

🔄 プロンプトキャッシュ共有

再利用されるコンテキストのキャッシュに対応 (API Changelog ではプロンプトキャッシュ共有と記載)。キャッシュ済み入力は $0.01 / 100 万トークンで処理でき、30 分および 12 時間のキャッシュ書き込みに対応する。

🖼️ 質問インストラクション内の画像対応

質問の指示に画像を含められるようになり、視覚的な基準を使った意思決定の定義が可能になった。

📦 ネイティブ JSON 入力 (input_json)

input_json により構造化データをそのまま渡せる。テキスト化の前処理なしで、構造化入力に基づく意思決定ができる。

📈 質問数上限 400 問へ倍増

1 リクエストあたりの質問数上限が 200 問から 400 問に拡大。大量の分類・評価タスクをまとめて実行できる。

🌍 推論の地域内処理

推論の地域内処理 (inference residency) が米国と EU で利用可能に。対象顧客には Zero Data Retention も提供される。

3 つの回答タイプ

開発者は質問と許容される回答を定義し、テキスト、画像、ネイティブ JSON としてコンテキストを渡す。API は以下 3 種類のいずれかの回答タイプを返し、アプリケーションは次の動作を決定できる。

タイプ 用途 主な結果
predicate 条件が真である確率の推定 (例: 商品に目に見える損傷があるか) probability: 条件が真である確率の推定値 (0 から 1)
choice 事前定義した選択肢から 1 つを選択 (例: エージェントが続行・リトライ・確認質問のいずれを行うべきか) choice: 指定した値のいずれか。確率と信頼度も返される
score ルーブリックの順序付きレベルに対する評価 (例: 損傷の深刻度) score: レベルインデックスの確率加重平均

GPT-Live とのネイティブ統合によるリアルタイム音声体験

Decisions API は GPT-Live とネイティブに統合され、ライブ会話中の高速で焦点を絞った意思決定を支援する。公式記事では以下のユースケースが挙げられている。

  • カスタマーサポートエージェントが、確認質問をするか、リクエストをルーティングするか、エスカレーションするかを判断
  • アバターがユーザーの発話に応じて表情を調整し、言葉に基づいてウインクや笑顔で応答するインタラクティブな体験

実装としては、既存の GPT-Live セッションの session.triggers に設定を追加する。Live 側が decision.event を発行し、アプリケーションは選択された reaction を読み取ってキャラクターをアニメーションさせる、という流れが紹介されている。

JavaScript GPT-Live 統合のイメージ (公式記事で紹介された流れに基づく概念例) 
// 既存の GPT-Live セッションの session.triggers に設定を追加
session.update({
  triggers: [
    {
      type: "decision",
      question: {
        type: "choice",
        instruction: "ユーザーの発話に合うアバターの表情は?",
        choices: ["smile", "wink", "neutral", "surprised"]
      }
    }
  ]
});

// Live 側が decision.event を発行し、
// アプリケーションは選択された reaction を読み取って
// キャラクターをアニメーションさせる
session.on("decision.event", (event) => {
  animateCharacter(event.reaction);
});

🧭 利用の始め方

  • アプリケーションが頻繁に行う意思決定を 1 つ選び、質問、可能な回答、それらを区別するのに必要なコンテキストを定義して、実際の利用を反映した例でテストする進め方が推奨されている
  • Decisions Playground で自分のテキストや画像を使って試すか、開発者ガイド に従って最初のリクエストを作成できる

アーキテクチャ

クライアントはテキスト・画像・ネイティブ JSON と質問 (最大 400 問/リクエスト) を Decisions API に渡す。GPT-Live セッションからのトリガーにも対応し、GPT-6 Luna が 3 種類の型付き回答を返す。

開発者への影響

⚡ 小さな意思決定の高速化と低コスト化

分類、ルーティング、次アクション選択などの頻出タスクを、Responses API 経由の GPT-6 Luna より最大 10 倍高速に処理できる。出力トークン課金がないため、コスト見積もりが入力トークンのみで完結する。

🧩 型付き回答による後続処理の簡素化

predicate / choice / score の 3 タイプで回答形式が保証されるため、自由形式テキストのパースが不要になり、アプリケーションロジックに直接組み込める。

📚 バッチ的な質問処理

1 リクエストで最大 400 問 (ベータ時の 2 倍) を処理できるため、大量の分類・評価タスクをまとめて実行できる。

🎙️ 音声アプリケーションへの組み込み

GPT-Live とのネイティブ統合により、ライブ会話中のエスカレーション判断や表情制御など、リアルタイム性が求められる意思決定を実装できる。

🛡️ コンプライアンス要件への対応

米国・EU での地域内処理と Zero Data Retention (対象顧客向け) により、データ所在やデータ保持の要件があるワークロードでも採用しやすい。

💸 キャッシュによるコスト最適化

再利用されるコンテキストをプロンプトキャッシュ ($0.01 / 100 万トークン) で処理でき、同じ指示・ルーブリックを使い回す意思決定で効果が大きい。

まとめ

Decisions API が GPT-6 Luna で一般提供開始となった。答えが限定された質問に特化することで、テキスト・画像・ネイティブ JSON からの意思決定を Responses API 経由の GPT-6 Luna より最大 10 倍高速に処理し、predicate / choice / score の 3 つの型付き回答を返す。料金は入力 $0.10 / 100 万トークン、キャッシュ済み入力 $0.01 / 100 万トークンで、出力トークンへの課金はない。ベータからの進化として、GPT-Live ネイティブ統合、プロンプトキャッシュ、米国・EU の地域内処理、ネイティブ JSON 入力、質問インストラクション内の画像対応、質問数上限の 400 問への倍増が加わり、分類・ルーティング・リアルタイム音声まで幅広いユースケースに対応する基盤が整った。
