🛡️ OpenAI と Cisco が「Shirudo」を発表

パッチ適用前の稼働中 Linux システムを守るオープンソースランタイム — 名前は日本語の「盾」に由来

📅 2026-11-23 | ソース: OpenAI News/Blog

概要

🤝

OpenAI と Cisco の共同発表

2026 年 11 月 23 日、両社はオープンソースのセキュリティランタイム「Shirudo」(日本語の「盾」に由来) を共同発表した。

⏱️

パッチ適用までの「空白期間」を埋める

脆弱性の公開からパッチのテスト・展開までには数日から数週間かかることがある。その間のギャップを「シールド」と呼ばれる一時的な保護で埋める。

🔄

再起動なしで稼働中システムを保護

パッチの適用や再起動を待たずに、稼働中の Linux システムを保護することを目的としたランタイム。

🧪

実証テスト: Java4Shell 攻撃をブロック

Codex が生成したシールドが、稼働中の Elasticsearch サービスに対する Java4Shell 攻撃を再起動なしでブロック。Java の Base64 デコーダに入力チェックを追加し、悪意ある入力を拒否した。

🆓

GitHub で即時利用可能

BSD 2-Clause ライセンス (BPF プログラムは BSD/GPL デュアルライセンス) で無料公開されている。

Before / After: 脆弱性公開後の対応

Before: Shirudo なし

  • パッチのテスト・展開まで数日〜数週間の無防備な空白期間
  • 保護の適用にはプロセスの再起動が必要
  • 計画外のダウンタイムが発生しうる

After: Shirudo あり

  • シールドによる一時的な保護で空白期間をカバー
  • 稼働中のプロセスに再起動なしで適用
  • 適用前に影響を監視し、展開はセキュリティチームが判断

Shirudo の 4 つの中核機能

🛡️ ライブ保護

再起動なしで脆弱なコードパスをブロックする。シールドの適用前に影響を監視することも可能。

⚡ マシンスピードの防御

AI エージェントが脆弱性を調査し、シールドを開発・検証する。展開の最終判断はセキュリティチームが行う。

🔏 信頼できる展開

シールドは暗号署名され、ロード前に検証される。eBPF ベリファイアとカーネルのセキュリティ制御が安全性を担保する。

🔐 ハードウェアベースの検証

TPM (Trusted Platform Module) により、保護の適用・削除の検証可能な記録を提供する。

両社の役割

🟢 OpenAI

Codex を含むフロンティア AI と、セキュリティ・インフラ研究を提供。

🔵 Cisco

インフラとセキュリティの専門知識を提供。傘下の Isovalent がデモとセルフガイドラボを提供。

「あるチームがシステムを守るより良い方法を見つけたとき、他のチームはゼロから始める必要がない」

"when one team finds a better way to protect a system, others don't have to start from scratch"

— Greg Brockman 氏 (OpenAI 社長・共同創業者)。多くのチームが同じソフトウェアに依存しているため、オープンに構築する意義を強調

長期的ビジョン

Shirudo プロジェクトは、脅威に適応できるインフラの実現を目指している。

🧱 カーネル・コアサービスの強化

カーネルやコアサービスを強化し、攻撃に強い基盤を作る。

🔒 ワークロード権限の最小化

ワークロードに与える権限を最小限に抑える。

🚨 侵害の検出・封じ込め

侵害を検出し、被害の拡大を封じ込める。

♻️ 検証済み正常状態への復旧

検証済みの正常状態へシステムを復旧させる。

🎯 将来の目標

脆弱性開示と同時に、テスト済みシールドを提供することを目指している。

技術的な詳細

Shirudo は Linux の eBPF を利用している。eBPF により、Linux カーネル内の特定ポイントで小さなプログラムを実行し、不審な活動の監視と標的を絞った保護が可能になる。

🔁 防御の流れ

AI エージェントによる調査: AI エージェント (Codex など) が公開された脆弱性を調査し、シールドを開発・検証する

暗号署名: シールドは暗号署名され、ロード前に署名が検証される

安全性の担保: eBPF ベリファイアとカーネルのセキュリティ制御がシールドの安全性を担保する

人間による最終判断: セキュリティチームが展開を最終判断し、稼働中のプロセスに再起動なしで適用する

TPM による記録: TPM が保護の適用・削除の検証可能な記録を残す

🧪 実証テスト: Java4Shell 攻撃のブロック

Java の Base64 デコーダに入力チェックを追加するシールドを、稼働中の Elasticsearch プロセスに直接適用し、悪意ある入力を拒否した。詳細は Isovalent のブログで公開されている。

Pseudocode シールドの動作イメージ (概念を示す擬似コード) 
# 実証テストのシールドの概念イメージ (実際のコードではない)
# 稼働中の Elasticsearch プロセスに再起動なしで適用

def base64_decode_shield(input_data):
    # シールド: Base64 デコーダへの入力チェックを追加
    if is_malicious(input_data):      # Java4Shell 攻撃パターンを検出
        reject(input_data)            # 悪意ある入力を拒否
    else:
        pass_through(input_data)      # 正常な入力はそのまま処理

※ 上記は報告された動作を説明するための擬似コードであり、実際の実装は GitHub リポジトリを参照。

開発者への影響・ユースケース

⏳ パッチ適用までの空白期間を短縮

脆弱性公開からパッチ展開までの間、再起動なしの一時的な保護を適用でき、計画外のダウンタイムを避けられる。

🆓 無料で即時利用可能

GitHub で公開済みのオープンソース (BSD 2-Clause、BPF プログラムは BSD/GPL デュアルライセンス) であり、開発者・セキュリティ研究者・インフラ運用者がすぐに試せる。

🧑‍💼 人間による最終判断を維持

AI エージェントがシールドを生成・検証するが、展開の判断はセキュリティチームが行うため、既存の運用プロセスに組み込みやすい。

🌱 コミュニティ貢献の機会

ランタイム本体、新しいシールド、Linux/eBPF への改善など、コミュニティからの貢献が歓迎されている。

まとめ

Shirudo は、OpenAI のフロンティア AI (Codex) と Cisco のインフラ・セキュリティ専門知識 (Isovalent を含む) を組み合わせたオープンソースランタイムであり、eBPF を使って稼働中の Linux システムに再起動なしの「シールド」を適用する。シールドは暗号署名と eBPF ベリファイアで検証され、TPM により適用・削除の記録が残るため、信頼性の高い運用が可能である。パッチ適用までの空白期間を埋める新しい防御手段として、2026 年 12 月 15 日の技術ウェビナーなどを通じてコミュニティへの展開が進められる。
