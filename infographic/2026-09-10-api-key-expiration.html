API 更新

🔑 プロジェクト API キーに有効期限を設定可能に

組織・プロジェクトレベルでの最大キー寿命の強制にも対応

📅 2026-09-10 | OpenAI API Changelog

概要

2026 年 9 月 10 日、OpenAI はプロジェクト API キーの作成時に有効期限 (expiration date) を設定できる機能を発表。無期限キーの放置による運用リスクを軽減し、短寿命クレデンシャルのセキュリティプラクティスを標準機能として実現できる。

⏳

プロジェクト API キーの有効期限設定

キー作成時に有効期限を指定でき、期限を過ぎたキーは自動的に失効する。手動での失効 (revoke) 忘れによる長期残存リスクを解消

🏢

組織・プロジェクトレベルでの最大キー寿命の強制

管理者は Platform 設定で最大キー寿命 (maximum key lifetime) を強制可能。新規作成キーは設定された上限期間内に失効することが必須になる

🛡️

セキュリティの構造的強化

キー漏洩時の被害期間の限定、「ゾンビキー」の自動防止など、キー管理のセキュリティを構造的に強化するアップデート

🔄

キーローテーション運用の整備が必要

開発者には期限前のキー差し替え手順の整備と、期限切れによる認証エラー (401) への備えが求められる

Before / After

Before

キーは作成後、無期限で有効であり続ける。不要になったキーは手動で失効させる運用が必要で、削除し忘れたキーが長期間有効なまま残存するリスクがあった

After

作成時に有効期限を指定でき、期限到達で自動失効。さらに組織・プロジェクトレベルのポリシーとして最大キー寿命を強制し、無期限キーの作成自体を防止できる

主な機能

⏰ 有効期限付きキーの作成

プロジェクト API キーの作成時に有効期限を指定可能。"You can now set expiration dates when creating project API keys." と Changelog に明記されている

🌐 組織レベルのポリシー

組織全体のポリシーとして、すべてのプロジェクトで作成されるキーに最大寿命を適用できる

📁 プロジェクトレベルのポリシー

特定プロジェクトに対して個別に最大寿命を適用でき、プロジェクトごとに異なるセキュリティ要件に対応可能

🚫 新規キーへの強制適用

ポリシー設定後に「新規作成されるキー」が強制の対象。上限期間内に失効する有効期限の指定が必須となる

⚙️ Platform 設定から構成

有効期限の設定と最大キー寿命の強制は、Platform 設定 (ダッシュボード) 経由で行う

⚠️ 既存キー (設定前に作成されたキー) への遡及適用の有無、Admin API からのプログラマティックな設定可否、指定可能な期限の粒度・上限下限値は Changelog に明記されておらず、公式ドキュメントでの確認が必要

セキュリティ上の意義

🔐 キー漏洩時の被害期間の限定

有効期限付きキーは、万一漏洩しても悪用可能な期間が期限までに限定される。無期限キーの放置による長期的なリスクを構造的に排除でき、「クレデンシャルは短寿命であるほど安全」という原則を標準機能として実践できる

📋 組織ガバナンスとコンプライアンス対応

個々の開発者の運用任せではなく、組織・プロジェクトレベルのポリシーとして最大寿命を強制できるため、定期的なクレデンシャルローテーションの義務付けなどのコンプライアンス要件への対応が容易になる

🧟 「ゾンビキー」の自動防止

退職者や終了したプロジェクトのキーが失効されずに残る、いわゆる「ゾンビキー」の発生を期限切れによって自動的に防止。棚卸し漏れのリスクを解消できる

開発者への影響

🔄

キーローテーション運用の設計が必要

期限前に新しいキーを発行してアプリケーションに反映するローテーション手順 (シークレットマネージャーとの連携、デプロイパイプラインでの差し替えなど) の整備が必要

🚨

期限切れによる障害への備え

失効に気付かないと本番環境で認証エラー (401) が発生。期限の監視・通知の仕組みやアラート設定を検討すべき。プラットフォーム側の期限接近通知機能の有無は公式情報での確認が必要

🔍

組織ポリシー適用時の影響確認

最大キー寿命の強制後は無期限キーを選択できなくなる。CI/CD やバッチ処理で長期間キーを使い続けている場合は、運用フローの見直しが必要

📶

段階的な導入が可能

強制の対象は「新規作成されるキー」のため、まず新規キーから有効期限運用を開始し、既存キーを順次置き換える移行戦略が取りやすい

まとめ

プロジェクト API キーへの有効期限設定と、組織・プロジェクトレベルでの最大キー寿命の強制は、API キー管理のセキュリティを構造的に強化するアップデート。キー漏洩時の被害期間を限定し、ゾンビキーの残存を防止できる一方、開発者には期限前のキーローテーション運用と期限切れ監視の整備が求められる。Admin API からの設定可否や期限接近通知の有無など、Changelog に記載のない詳細は公式ドキュメントでの確認が必要である。
