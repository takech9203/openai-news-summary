Cogent と OpenAI、企業向けサイバー防御ファクトリーを構築

GPT-6.1 Sol / GPT-6 Astra / GPT-5.6 とエンタープライズコンテキストで、脆弱性の調査から検証済み修復までを自律化

📅 2026-11-10 | OpenAI News

概要

Cogent Security は、OpenAI のモデルと自社のエンタープライズコンテキストを組み合わせ、企業向けに「Cyber Defense Factories (サイバー防御ファクトリー)」を構築している。企業セキュリティにおける最大の課題は脆弱性の発見ではなく修復 (remediation) にあると捉えている。

🏭

修復こそが最大の課題

修復作業は複数チームにまたがる複雑な作業であり、攻撃者がどのように脆弱性を悪用し得るか、どのビジネスシステムが影響を受けるか、どの変更を安全に実施できるかといった、企業環境への文脈的理解が不可欠。

🤖

調査から検証済み修復までを自律処理

GPT-6.1 Sol と GPT-5.6 を自社のエンタープライズコンテキストおよび制御機構と組み合わせ、エージェントがエクスポージャーを評価し、許可された変更を実行し、リスクが排除されたことを確認する。

⚡

防御側をマシンスピードへ

脆弱性の発見と悪用が加速する状況に対応し、防御側がマシンスピードで動けるように設計されている。

🧠

「エンタープライズのためのメモリハーネス」

Context Engine によるコンテキストの再利用で「新しいタスクが発生するたびに世界の姿を学び直す必要がない」(共同創業者兼 CTO の Geng Sng 氏)。レイテンシ、推論コスト、結果の不整合を削減する。

📊

定量的な顧客成果

Fortune 1000 自動車関連企業で平均修復時間 (MTTR) 75% 削減、Fortune 500 IT サービス企業で脆弱性トリアージのスループット 5 倍を達成。

主要機能: コンテキストと行動権限を与える仕組み

エージェントに環境の共通理解を提供する Context Engine と、安全性を担保する多層の制御構造で構成される。顧客は、調査のみを委任する、変更に承認を必須とする、範囲を限定した自律修復を許可する、といった選択ができる。

🗺️ Context Engine

顧客ごとに資産、脆弱性、アイデンティティ、所有権、依存関係からなるエンタープライズナレッジグラフを維持。専用のバックグラウンドエージェントがセキュリティツールとシステム間の情報を継続的に照合し、調査エージェントと修復エージェントに環境の共通理解を提供する。事前計画と複雑な推論は GPT-6 Astra が担当。

📜 Agent Policies

企業ごとに許可された変更と承認要件を定義する。

🛡️ TRACE (ポリシー強制エンジン)

実行前にツール呼び出しをポリシーと照合する。チェックは決定論的で、別途のモデル推論を必要としない。

🚪 Agent Gateway

独立して認可をチェックし、リスクの高い作業は分離されたサンドボックスで実行可能。

技術詳細: アーキテクチャ

バックグラウンドエージェントがエンタープライズ環境の情報を Context Engine に集約し、調査・修復エージェントが OpenAI モデルを活用。修復の実行は Agent Policies → TRACE → Agent Gateway の多層制御を経てビジネスシステムに適用される。

モデルの使い分け

複雑な調査には推論品質を優先し、単純な作業にはコストを優先する。大規模エージェントスウォームのコスト効率を確保している。

GPT-6 Astra

Context Engine における事前計画と複雑な推論を担当

GPT-6.1 Sol

汎用的な実行に使用

GPT-5.6

高度な推論の重要性が低い定型的な脆弱性管理タスクに使用

「OpenAI モデルは他のプロバイダーと比べてコスト効率が高い。巨大なエージェントスウォームを動かす場合、これは大きな利点だ」 — Geng Sng 氏 (Cogent 共同創業者兼 CTO)

Cogent が OpenAI モデルと Codex を選ぶ理由

Cogent はクローズドソースとオープンソースの代替モデルを継続的に評価しており、OpenAI モデルについて以下の優位性を報告している。

🧩 長時間タスクでの強力な推論

長時間実行のセキュリティタスクにおいて、より強力な推論を発揮する。

🎯 高い忠実度

より高い忠実度と、技術的なコードベースにおけるハルシネーションの少なさ。

🔗 信頼性の高い実行

修復ワークフロー全体でコンテキストを保持しながら、ツール呼び出しを逐次・並列に連鎖できる。

🛠️ エンジニアリング負荷の削減

OpenAI API は「リクエストルーティングとエージェントオーケストレーションを合理化し、社内のエンジニアリングオーバーヘッドを大幅に削減して、複雑なセキュリティワークフローの市場投入までの時間を短縮した」。修復とパッチ適用のために構築すべき支援ソフトウェアも削減された。エンジニアの多くは開発に Codex を選択しており、オープンソースのコーディング環境で同じモデルを使うよりも生産性が高いとしている。

ユースケース

🚨 PHP2Shell 対応: 脆弱性開示から検証済み修正まで

Web サイトの実行に使われるプログラミング言語 PHP で「PHP2Shell」と呼ばれる重大なセキュリティ欠陥が開示された際、顧客は環境にすでに展開されていた Cyber Defense Factories を活用した。GPT-6.1 Sol と GPT-6 Astra が調査と修復計画のための深い推論を提供。エージェントは Cogent のコンテキストレイヤーを使って影響を受けるシステムを特定し、エクスポージャーを評価し、アプリケーションの依存関係と運用上の制約を考慮した計画を策定した。その後、顧客が定義した承認・実行ワークフローに沿って修正をオーケストレーションし、解決を検証した。

📈 MarketAxess: 攻撃者視点での修復優先順位付け

取引プラットフォームの MarketAxess は、修復の優先順位付けに Cogent を活用している。

「Cogent は攻撃者の視点で当社の環境を見る。インターネットから脆弱なシステムまでの経路をたどり、その途中の制御を確認する。当社の修復作業は今や、最大のリスクと攻撃者が侵入に使い得る経路に集中している」 — Vijay Bala 氏 (MarketAxess グローバル CISO)

🔴 攻撃研究との連携: Trusted Access for Cyber and Daybreak

Cogent は「Trusted Access for Cyber and Daybreak」を通じて、社内のレッドチーミングと攻撃経路研究に対する技術支援を受けている。Daybreak 内のアクセス階層である Daybreak Red は、認可された攻撃・脆弱性研究のための専用 OpenAI モデルをチームに提供する。「良い防御には良い攻撃が必要だ」と Geng Sng 氏は語る。

今後の展開: 自律的サイバー防御の拡大

  • 単純な構成変更から複数のエンタープライズシステムにまたがるマルチステップワークフローまで、エージェントが実行できる修正の範囲と複雑さを広げる、より自律的な修復
  • 自律的な発見と検証の開発。すべての脆弱性から継続的に学習して将来の調査と修正を改善しながら、リスクを発見・排除するクローズドループシステムの実現を目指す

開発者・企業への影響

  • 修復の自動化: 脆弱性の発見から検証済み修復までをエージェントが一貫して処理するモデルが、エンタープライズで実運用段階に入ったことを示す事例
  • 定量的効果: 平均修復時間 75% 削減、トリアージスループット 5 倍など、具体的な成果が報告されている
  • ガバナンス設計の参考: Agent Policies、決定論的なポリシーチェック (TRACE)、独立した認可 (Agent Gateway)、サンドボックス実行という多層制御は、自律エージェントを本番環境で安全に動かすための設計パターンとして参考になる
  • モデルの使い分け: 複雑な推論には上位モデル (GPT-6 Astra / GPT-6.1 Sol)、定型タスクには低コストモデル (GPT-5.6) という使い分けにより、大規模エージェントスウォームのコスト効率を確保
  • コンテキスト再利用: ナレッジグラフによる「メモリハーネス」でコンテキストを再利用し、レイテンシ・推論コスト・結果の不整合を削減するアプローチ

まとめ

  • Cogent Security は、GPT-6.1 Sol、GPT-6 Astra、GPT-5.6 と自社のコンテキストエンジン・ポリシー制御を組み合わせた Cyber Defense Factories により、企業の脆弱性修復を自律化
  • PHP2Shell 脆弱性への対応では、調査から検証済み修復までをエージェントが実行
  • 顧客は平均修復時間 75% 削減や脆弱性トリアージ 5 倍のスループットといった成果を達成
  • Trusted Access for Cyber and Daybreak による攻撃研究も活用し、リスクを発見・排除しながら継続的に学習するクローズドループシステムの実現を目指す
