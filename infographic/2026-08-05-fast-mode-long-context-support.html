API 更新

Fast mode が GPT-5.6 Sol / Terra / Luna の長文コンテキスト (272K トークン超) に対応

発表日: 2026-08-05 | ソース: OpenAI API Changelog

概要

OpenAI は 2026 年 8 月 5 日、API Changelog にて Fast mode が GPT-5.6 Sol / GPT-5.6 Terra / GPT-5.6 Luna の長文コンテキストリクエストに対応したことを発表した。2026 年 7 月 30 日の Fast mode 導入時に存在した長文コンテキスト非対応の制約が、約 1 週間で解消された。

📜

272K トークン超のプロンプトに対応

272K トークンを超える長文コンテキストリクエストでも Fast mode を利用できるようになった。大規模なドキュメント処理や長大なコンテキストを扱うアプリケーションでも高速処理の恩恵を受けられる。

⚡

Standard ティア比で最大 2.5 倍の速度

長文コンテキストでも Standard ティア比で最大 2.5 倍の速度が得られる ("delivering speeds up to 2.5× faster than the Standard tier")。

🤖

対象は GPT-5.6 ファミリーの 3 モデル

gpt-5.6-sol、gpt-5.6-terra、gpt-5.6-luna の 3 モデルが対象。速度・品質・コストのバランスに応じて選択できる。

💰

料金は Standard の長文コンテキスト料金の 2 倍

長文コンテキストの Fast mode 料金は Standard ティアの長文コンテキスト料金のちょうど 2 倍。短コンテキストの Fast mode 料金は導入時から変更なし。

🔧

コード変更は最小限

すでに service_tier: "fast" (または "priority") を指定しているアプリケーションでは、長文リクエストが自動的に Fast mode の対象となる。

Changelog 原文: "Fast mode now supports long-context requests for GPT-5.6 Sol, GPT-5.6 Terra, and GPT-5.6 Luna."

主な内容

📜 長文コンテキストリクエストへの対応

272K トークンを超えるプロンプト ("long-context prompts exceeding 272K tokens") が Fast mode で実行可能になった。対象は gpt-5.6-sol / gpt-5.6-terra / gpt-5.6-luna の 3 モデル。

🔓 導入時の制約の解消

2026-07-30 の導入時点では長文コンテキスト、ファインチューニング済みモデル、Embeddings が非対応だった。今回の更新で、このうち長文コンテキストの制約が GPT-5.6 ファミリーの 3 モデルで解消された。

💵 長文コンテキストの Fast mode 料金

Changelog エントリ自体には価格の記載はなく、料金ページへのリンクが案内されている。長文 Fast mode 料金は Standard ティアの長文コンテキスト料金のちょうど 2 倍に設定されている。

🔄 後方互換性の維持

service_tier パラメータに "fast" を指定する。後方互換の "priority" も引き続き有効で、既存アプリケーションは変更不要。

技術的な詳細

利用方法は従来の Fast mode と同一。Responses API (v1/responses) または Chat Completions API (v1/chat/completions) で service_tier パラメータに "fast" (後方互換の "priority" も有効) を指定する。272K トークンを超えるプロンプトは、今回の更新以降 Fast mode で処理され、長文コンテキスト料金が適用される。実際に使用されたティアは、レスポンスオブジェクトの service_tier フィールドで確認できる。

Python Responses API で長大な入力を Fast mode で処理する例 
from openai import OpenAI

client = OpenAI()

# 272K トークンを超える長文ドキュメントを読み込む
with open("large_document.txt") as f:
    document = f.read()

response = client.responses.create(
    model="gpt-5.6-sol",
    input=f"以下のドキュメントを要約してください。\n\n{document}",
    service_tier="fast",  # 長文コンテキストでも Fast mode が適用される
)

print(response.output_text)
print(response.service_tier)  # 実際に使用されたティアを確認
Bash curl での利用例 
curl https://api.openai.com/v1/responses \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.6-terra",
    "input": "<272K トークンを超える長文プロンプト>",
    "service_tier": "fast"
  }'

ユースケースと開発者への影響

📚 長文ワークロードの高速化

大規模コードベースの解析、長大なドキュメントの要約、大量の会話履歴を含むリクエストなど、272K トークンを超えるワークロードでも最大 2.5 倍の速度が得られるようになった。レイテンシが重要な長文アプリケーションに最適。

🔧 既存アプリケーションへの自動適用

すでに service_tier: "fast" (または "priority") を指定しているアプリケーションでは、長文リクエストが自動的に Fast mode の対象となる。新たなパラメータの追加は不要で、コード変更は最小限。Sol だけでなく Terra / Luna も対応しているため、速度・品質・コストのバランスに応じて 3 モデルから選択できる。

💰 コスト管理とプロンプトキャッシュの活用

長文コンテキストの Fast mode 料金は Standard の 2 倍。特に gpt-5.6-sol では入力 $20.00 / 出力 $90.00 (100 万トークンあたり) と高額になるため、レイテンシ要件のないバッチ処理では Standard や Batch API の利用を検討すべき。キャッシュ入力は通常入力の 10 分の 1 の価格であり、長文コンテキストでは特にキャッシュヒットによるコスト削減効果が大きい。

まとめ

2026 年 8 月 5 日の更新により、Fast mode は GPT-5.6 Sol / Terra / Luna の 3 モデルで 272K トークンを超える長文コンテキストリクエストに対応した。速度は Standard ティア比で最大 2.5 倍、料金は Standard の長文コンテキスト料金の 2 倍である。2026-07-30 の Fast mode 導入時に存在した長文コンテキスト非対応の制約が約 1 週間で解消されたことで、レイテンシが重要な長文ワークロードを持つ開発者は、既存の service_tier 指定のまま高速処理の恩恵を受けられるようになった。
