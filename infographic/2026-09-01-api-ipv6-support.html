概要

2026 年 9 月 1 日付の OpenAI API Changelog にて、api.openai.com への接続で IPv6 が利用可能になったことが発表されました。これまで IPv4 経由での接続が前提だった OpenAI API エンドポイントに対し、IPv6 プロトコルによる接続が可能になります。

🌐

api.openai.com が IPv6 接続に対応

対象エンドポイントは api.openai.com。IPv6 プロトコルでの接続が可能になりました。

✅

既存クライアントへの変更は不要

IPv4 での接続は引き続き利用できるため、既存のクライアントに変更は不要です。

🔀

デュアルスタック環境では IPv6 経由の接続が発生し得る

OS や HTTP ライブラリの名前解決の挙動 (Happy Eyeballs など) に応じて、IPv6 経由で接続する可能性があります。

📄

Changelog の記載は一文のみ

エントリは "Connections to api.openai.com can now use IPv6." という簡潔な記載のみで、IPv6 アドレス範囲、DNS レコードの詳細、移行手順などの追加情報は現時点で含まれていません。

Before / After — 接続プロトコルの変更

❌ Before (変更前)

IPv4 経由での接続が前提でした。

  • api.openai.com への接続は IPv4 のみ
  • IPv6 オンリー環境では NAT64/DNS64 などの変換機構が必要になる場合がある

✅ After (変更後)

IPv6 プロトコルでの接続に対応しました。

  • IPv4 での接続は引き続き利用可能 (既存クライアントは変更不要)
  • デュアルスタック環境では名前解決の挙動に応じて IPv6 経由で接続する可能性

主な内容 — 変更内容

🎯 対象エンドポイント api.openai.com
🔧 変更点 IPv6 プロトコルでの接続に対応
💡 IPv4 での接続は引き続き利用できるため、既存のクライアントに変更は不要です。デュアルスタック環境のクライアントは、OS や HTTP ライブラリの名前解決の挙動 (Happy Eyeballs など) に応じて、IPv6 経由で接続する可能性があります。

背景 — IPv6 対応の一般的な意義

IPv6 対応は、以下のような環境で API を利用する開発者にとって意味を持ちます。

🌍 IPv6 オンリーのネットワーク

NAT64/DNS64 などの変換機構を経由せずに直接接続できる可能性があります。

📱 モバイルネットワーク

多くの通信事業者が IPv6 を優先するネットワークを運用しています。

☁️ クラウド環境

IPv6 オンリーのサブネットや、IPv4 アドレスコストの削減を目的とした構成での利用が考えられます。

⚠️ これらは IPv6 対応一般に関する説明であり、OpenAI が公式に言及した内容ではない点に注意してください。

開発者への影響

✅ 既存アプリケーション

変更は不要です。IPv4 での接続は引き続き動作します。

🔀 デュアルスタック環境

クライアントの名前解決の挙動によっては、今後 IPv6 経由で api.openai.com に接続される可能性があります。

🛡️ ファイアウォール / egress 制御

IPv4 アドレスベースで OpenAI API への通信を許可している環境では、IPv6 経由の接続がブロックされる、あるいは意図せず許可される可能性があります。egress ルールを IP アドレスで管理している場合は、IPv6 の扱いを確認することを推奨します。公式の IPv6 アドレス範囲は Changelog には記載されていないため、必要に応じて公式ドキュメントやサポートで最新情報を確認してください。

📊 プロキシ / 監視

接続ログや監視ツールで送信元・宛先アドレスを扱っている場合、IPv6 アドレス形式のログが出力される可能性を考慮してください。

ユースケース — 確認しておきたいシナリオ

🛡️ egress 制御を IP アドレスで管理しているシステム

IPv4 アドレスベースの許可ルールのみを設定している場合、IPv6 経由の接続がブロックされる、あるいは意図せず許可される可能性があります。IPv6 の扱いを確認し、必要に応じて公式ドキュメントやサポートで最新情報を確認しましょう。

🔀 デュアルスタック環境で動作するアプリケーション

OS や HTTP ライブラリの名前解決の挙動 (Happy Eyeballs など) に応じて、今後 IPv6 経由で api.openai.com に接続される可能性がある点を把握しておきましょう。

📊 接続ログ・監視ツールを運用しているチーム

送信元・宛先アドレスをログや監視で扱っている場合、IPv6 アドレス形式のログが出力される可能性を考慮した運用が必要です。

まとめ

api.openai.com が IPv6 接続に対応しました。既存の IPv4 クライアントへの影響はありませんが、デュアルスタック環境やファイアウォールで egress 制御を行っている環境では、IPv6 経由の接続が発生し得る点を確認しておくとよいでしょう。Changelog の記載は一文のみであり、IPv6 アドレス範囲などの詳細は公式ドキュメントの更新を待つ必要があります。
