概要

2026 年 9 月 3 日、OpenAI は最上位モデル GPT-6 Astra を Responses API と Chat Completions API でリリースしました。「最も困難なエンドツーエンドの作業のために構築された、最も高性能なモデル」と位置付けられ、提供されたコンテキストとツールを使って複雑なタスクを最初の依頼から完成まで遂行できます。

🚀

最上位モデル GPT-6 Astra が API で利用可能に

v1/responses と v1/chat/completions の両方でリリース。推論・コーディング・コンピュータ操作・調査 (リサーチ)・文書作成を組み合わせ、複雑なタスクをエンドツーエンドで遂行します。

🧠 推論 💻 コーディング 🖱️ コンピュータ操作 🔍 調査 📝 文書作成
⏳

Responses API に長時間タスク向け新機能が 3 つ追加

非同期ツール呼び出し、ターン途中のステアリング、会話途中での推論努力レベル変更という、GPT-6 Astra での長時間実行タスクを制御するための機能が同日追加されました。

🔧

ツール呼び出しは Responses API が必須

Chat Completions API でツールを使用している場合は、Responses API への移行ガイドに従う必要があります。

🚫

一部パラメータが非対応に

推論努力レベル none、カスタムの temperature、top_p、logprobs は GPT-6 Astra では非対応です。

🛡️

Preparedness Framework で初の Critical レベル

GPT-6 Astra はサイバーセキュリティ能力が初めて Critical レベルに達したモデルです。安全対策の詳細は「Path to Astra」(2026-09-01) および「Safety overview: GPT-6 Astra」(2026-09-03) で説明されています。

主な内容 — Responses API の長時間タスク向け新機能

GPT-6 Astra での長時間実行作業向けに、以下の 3 つの制御機能が v1/responses に追加されました。

1

🔄 非同期ツール呼び出し

Async Tool Calling

アプリケーション側が function ツールやカスタムツールを実行している間もモデルが作業を継続し、ツールの結果が利用可能になり次第返却できます。

2

🎮 ターン途中のステアリング

Mid-turn Steering

WebSocket 経由でレスポンス生成中に追加指示を送信でき、修正や要件変更を実行中のモデルに反映できます。

3

🎚️ 会話途中での推論努力レベル変更

Reasoning Effort Change

キャッシュ済みプロンプトのプレフィックスを保持したまま、難しい作業では推論努力レベルを上げ、定型的なフォローアップでは下げることができます。

API 変更点 — 移行時の注意点

GPT-6 Astra は既存モデルと同じ感覚では使えません。移行にあたっては非対応パラメータとツール呼び出しの制約に注意が必要です。

🚫 非対応 (使えなくなるもの)

  • 推論努力レベル none
  • カスタムの temperature
  • カスタムの top_p
  • logprobs
  • Chat Completions API でのツール呼び出し (Responses API への移行が必要)

✅ 対応 (新たに使えるもの)

  • v1/responses での GPT-6 Astra 利用
  • v1/chat/completions での GPT-6 Astra 利用 (ツールなし)
  • 非同期ツール呼び出し (Responses API)
  • WebSocket 経由のターン途中ステアリング
  • 会話途中での推論努力レベル変更 (キャッシュ保持)
項目 内容
対象エンドポイント v1/responses、v1/chat/completions
新モデル GPT-6 Astra (推論・コーディング・コンピュータ操作・調査・文書作成)

安全機構 ミスアライメント監視による非同期チェック (安全アラート・会話停止の可能性あり)

技術的な詳細 — コードサンプル

Responses API での GPT-6 Astra の基本的な呼び出し例です (公式の「Using GPT-6 Astra」ガイドを参照のこと)。

Python Responses API での GPT-6 Astra の基本的な呼び出し例 
from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="gpt-6-astra",
    input="リポジトリ全体を調査し、リファクタリング計画を作成してください。",
    tools=[
        {
            "type": "function",
            "name": "run_tests",
            "description": "テストスイートを実行する",
            "parameters": {"type": "object", "properties": {}},
        }
    ],
)
print(response.output_text)

開発者への影響

🚚 Responses API への移行が実質的に必須に

GPT-6 Astra でツール呼び出しを利用するには Responses API が必要なため、Chat Completions API でツールを使用している既存アプリケーションは移行ガイドに従った対応が求められます。

🔍 サンプリング系パラメータの見直しが必要

temperature、top_p、logprobs に依存した実装 (出力の多様性制御やログ確率を利用した後処理など) は、GPT-6 Astra では動作しないため設計の見直しが必要になります。

⚡ 長時間タスクの設計自由度が向上

非同期ツール呼び出しにより、時間のかかるツール実行中もモデルが作業を継続できるため、エージェント型アプリケーションのスループット改善が期待できます。

🎮 実行中のタスクに介入できる

WebSocket 経由のターン途中ステアリングにより、長時間タスクを最初からやり直すことなく、途中で修正指示や要件変更を反映できます。

💰 コストと品質の動的な調整が可能に

会話途中で推論努力レベルを変更でき、キャッシュ済みプレフィックスを保持したまま、タスクの難易度に応じてコストとレイテンシを最適化できます。

🛡️ 安全機構の挙動を考慮した設計が必要

ミスアライメント監視により安全アラートの発報や会話停止が発生し得るため、エージェントワークフローではこれらのケースのハンドリングを考慮する必要があります。

ユースケース

🤖 長時間実行されるエージェント型ワークフロー

リポジトリ全体の調査とリファクタリング計画の作成のような複雑なタスクを、最初の依頼から完成までエンドツーエンドで遂行できます。非同期ツール呼び出しにより、テストスイートの実行のような時間のかかるツール実行中もモデルが作業を継続し、スループットを改善できます。

🎮 実行中タスクへのリアルタイム介入

WebSocket 経由のターン途中ステアリングにより、レスポンス生成中に追加指示を送信できます。長時間タスクを最初からやり直すことなく、途中で修正や要件変更を実行中のモデルに反映できます。

💰 タスク難易度に応じたコスト最適化

会話途中での推論努力レベル変更により、難しい作業では推論努力レベルを上げ、定型的なフォローアップでは下げるという運用が可能です。キャッシュ済みプロンプトのプレフィックスを保持したまま、コストとレイテンシを動的に最適化できます。

まとめ

GPT-6 Astra は、推論からコンピュータ操作までを組み合わせて複雑なタスクをエンドツーエンドで遂行する OpenAI の最上位モデルとして、Responses API と Chat Completions API でリリースされました。ツール呼び出しが Responses API 必須となり、サンプリング系パラメータが非対応になるなど、既存アプリケーションには移行対応が求められます。同時に追加された非同期ツール呼び出し・ターン途中ステアリング・推論努力レベルの動的変更という 3 つの新機能は、長時間実行されるエージェント型ワークフローの制御性を大きく高めるものであり、Responses API を中心としたエージェント開発への移行を加速させる更新と言えます。
