スタートアップ (顧客事例)

Greptile、GPT-6 Astra でコードレビューを超えたバグ検出を実現

発表日: 2026-10-26 | ソース: OpenAI News/Blog

💬 「私たちはバグを減らし、世界のソフトウェアをより信頼できるものにするビジネスをしている」— 共同創業者兼 CEO、Daksh Gupta 氏

概要

🤖

コードベース全体の文脈を踏まえた AI エージェント

Greptile は、コードベース全体の文脈を踏まえてコード変更のレビューとテストを行う AI エージェントを開発するスタートアップ。その顧客事例が公開された。

📱

GPT-6 Astra でユーザーワークフローを実機テスト

コードを読むだけでは見つからない問題 (iPhone 表示でボタンが消えるなど) を、実際にアプリを動かして検出する。

🛡️

Daybreak で顧客のセキュリティ防御を強化

強力なモデルは攻撃者の悪用も容易にするため、スタートアップでも自社システムを簡単に守れる状態を目指す。

🔁

Codex と MCP 連携で手戻り (リバート) を削減

Knowledge Base の文脈を MCP サーバー経由で Codex に提供し、AI 生成コードのリバート率を低減。時間と推論コストを節約する。

主な取り組み

📱 アプリケーションの大規模テスト GPT-6 Astra

プルリクエストごとに開発サーバーを起動し、ブラウザを iPhone サイズのビューポートに変更してユーザー操作をシミュレート。モデルの視覚理解で画面を検査し、消えたボタンを発見できる。

  • 従来型の QA 会社のテストは現在の開発速度に対して「非現実的なほど遅い」と Gupta 氏は指摘

🛡️ セキュリティ防御強化 Daybreak

強力なモデルの普及で、従来は標的にならなかった企業もリスクに晒される。「スタートアップでも自社システムを簡単に守れるようにしたい」として、顧客の防御力が攻撃者の攻撃力を上回る状態を安全に実現することを目指す。

🔁 バグと手戻りの削減 Codex

Knowledge Base が企業のコードベースをインデックス化し、人間とエージェントの双方が読める形で文書化。MCP (Model Context Protocol) サーバー経由で Codex に提供し、顧客の既存パターンに沿ったコードを書けるようにする。

  • 「エージェントにコンテキストを与えるとリバートが減る」
  • Greptile 自身も「Codex のヘビーユーザー」として全部門で利用

🚀 今後の展望 Ultrafast

真のボトルネックはアイデアを動くソフトウェアに変換する速度であり、多くのタスクでモデルの知能は既に十分と Gupta 氏は考える。Ultrafast を開発高速化の手段と位置付け、エンタープライズソフトウェアの変更・リリースをサイドプロジェクト並みに容易にする検証機能を OpenAI と共に構築する意向。

開発者への影響

📱 UI レベルのバグ検出をプルリクエストごとに自動化

コードレビューに加え、実際のユーザー操作をシミュレートした UI レベルのバグ検出 (レスポンシブ表示の崩れなど) をプルリクエストごとに自動化できる事例が示された。

🔗 MCP 経由の文脈提供でリバート率を低減

MCP サーバー経由でコードベースの文脈をエージェントに提供することで、AI 生成コードのリバート率を下げ、時間と推論コストを削減できるパターンが実証された。

🛡️ あらゆる規模の組織でセキュリティ防御強化が重要に

強力なモデルの普及により攻撃側の能力も向上するため、スタートアップを含むあらゆる規模の組織でセキュリティ防御の強化が重要になる。

まとめ

Greptile は GPT-6 Astra による実アプリのワークフローテスト、Daybreak によるセキュリティ防御、Codex と MCP 連携による文脈提供という 3 つのアプローチで、コードレビューの枠を超えたバグ削減を実現している。数千の顧客が Codex を同社のナレッジベースに接続しており、エージェントへの文脈提供がリバート率低減につながることが示された。今後は Ultrafast を活用し、エンタープライズソフトウェアの変更・リリースを容易にする検証機能の構築を目指す。
